## مسارات البناء الجديدة

`android.yml` يعمل عند push وPR أو عند الطلب، ويمكن استدعاؤه من workflow آخر:

1. فحص الأدوات والبصمات والأمان وJavaScript واختبارات Python وJUnit وRoom وLint وتجميع اختبارات Android.
2. تشغيل اختبارات الجهاز على API 35 و36. اختبارات BBC وTrends والمقال العالمي الحي تبقى اختيارية خارج هذا المسار. اختبار ML Kit التقني الحقيقي مطلوب، ويصرّح CI بتنزيل النموذج.
3. بوابة تفحص التقارير الفعلية من المهمتين، وترفض حتى الفشل أو الإلغاء أو التخطي لأي مهمة إلزامية.
4. بناء QA APK معزول بعد اجتياز البوابة. اسم Artifact يوضح أنه للاختبار وليس تحديث التطبيق الشخصي.

`source-health.yml` يفحص RSS الحي عند الطلب دون مفاتيح AI أو استدعاءات مدفوعة. `personal-candidate.yml` يعيد الجودة أولًا ثم يتطلب مفاتيح توقيع أصلية داخل GitHub Secrets، ويطابق شهادة الإصدار السابق. مخرجه مرشح يحتاج قبول Galaxy، ولا ينشر GitHub Release أو يعلن قبوله النهائي.

Actions تستهلك من حصة حساب GitHub؛ لا خدمة اختبار مدفوعة ولا اشتراك جديد. تقييد دمج الفروع على خادم GitHub يعتمد على إمكانات خطة الحساب وإعداداته؛ لم يُدعَ تفعيل branch protection. ملفات CODEOWNERS وPR وبلاغ الأعطال وDependabot الشهرية أضيفت للمراجعة والمتابعة دون دمج تحديثات آلي.
